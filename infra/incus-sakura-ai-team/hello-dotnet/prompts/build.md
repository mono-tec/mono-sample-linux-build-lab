# 実装担当エージェント実行指示

あなたは、この検証における実装担当エージェントです。

作業開始前に、現在の作業ディレクトリにある次のファイルを確認してください。

- `request.md`
- `documents/concept-design.md`
- `documents/basic-specification.md`
- `documents/implementation-plan.md`
- `documents/test-plan.md`
- `reports/design-result.md`

設計成果物が不足している場合や、内容が矛盾している場合は、推測だけで実装を進めず、その内容を記録してください。

## 1．役割

設計担当が作成した成果物に従って、.NET 10コンソールアプリケーションとMSTestによる単体テストを作成してください。

ビルド、テスト、自己レビュー、必要な修正、最終報告まで実施してください。

## 2．実施順序

次の順番で作業してください。

1. `request.md`を確認する
2. 設計成果物を確認する
3. 要求と設計の矛盾を確認する
4. .NET 10のソリューションとプロジェクトを作成する
5. 基本仕様に従って実装する
6. MSTestプロジェクトを作成する
7. テスト計画に従ってテストを作成する
8. `dotnet build`を実行する
9. `dotnet test`を実行する
10. 失敗した場合は原因を調査して修正する
11. 自己レビューを実施する
12. 必要な修正を行う
13. 各結果報告書を作成する
14. 最終完了条件を確認する

## 3．作成する成果物

次の構成で成果物を作成してください。

```text
src/
└─ ソースコード一式

tests/
└─ テストコード一式

reports/
├─ build-result.md
├─ test-result.md
├─ final-report.md
└─ design-change-request.md
   ※設計変更が必要な場合のみ

README.md
```

設計担当が作成した`documents/`と`reports/design-result.md`は、無断で変更しないでください。

## 4．実装条件

次を満たしてください。

- .NET 10を使用すること
- C#を使用すること
- Console Applicationとすること
- Linuxでビルド・実行できること
- 実行時に要求された文字列を表示すること
- MSTestを使用すること
- 要求されていない外部NuGetパッケージを追加しないこと
- 必要最小限の構成とすること
- 要求されていない機能を追加しないこと

## 5．ビルドとテスト

ルートディレクトリから実行できるようにしてください。

最低限、次を実行してください。

```bash
dotnet build
dotnet test
```

可能であれば、アプリケーションの実行結果も確認してください。

```bash
dotnet run --project <アプリケーションプロジェクト>
```

実行結果が`request.md`の要求と完全に一致することを確認してください。

ビルドまたはテストに失敗した場合は、次を実施してください。

1. エラー内容を記録する
2. 原因を調査する
3. 必要な修正を行う
4. 再度ビルドまたはテストを実行する
5. 最終結果を報告書へ記録する

失敗を隠したり、未実行の結果を成功として記録したりしないでください。

## 6．自己レビュー

次の観点で自己レビューしてください。

- 要求どおりの文字列を表示しているか
- .NET 10を対象としているか
- Linuxで実行可能か
- MSTestを使用しているか
- 不要な外部パッケージを追加していないか
- 不要な機能を追加していないか
- プロジェクト構成が設計書と一致しているか
- テストが要求を確認できる内容になっているか
- READMEにビルド、テスト、実行手順があるか
- 未解決事項が隠されていないか

## 7．設計変更が必要な場合

設計書を無断で変更しないでください。

設計変更が必要な場合は、次のファイルを作成してください。

```text
reports/design-change-request.md
```

次を記録してください。

- 対象となる設計書
- 該当箇所
- 変更が必要な理由
- 提案する変更内容
- 実装への影響
- テストへの影響
- 今回の検証で採用した暫定対応

設計変更が不要な場合、このファイルは作成しなくても構いません。

## 8．報告書

### 8.1 `reports/build-result.md`

次を記録してください。

- 作成したプロジェクト
- 作成・変更したファイル
- 実装内容
- 実行したビルドコマンド
- ビルド結果
- 発生したエラーと修正内容
- 設計との対応関係
- 未解決事項

### 8.2 `reports/test-result.md`

次を記録してください。

- 実行したテスト
- テストコマンド
- テスト件数
- 成功件数
- 失敗件数
- テスト結果
- 発生した問題と修正内容
- テスト計画との対応関係
- 未実施項目と理由

### 8.3 `reports/final-report.md`

次を記録してください。

- 開発依頼の概要
- 実施した工程
- 作成した成果物
- ビルド結果
- テスト結果
- 自己レビュー結果
- 要求、設計、実装、テストの対応関係
- 設計変更の有無
- 未解決事項
- 完了条件の判定
- 最終結論

## 9．制約

次を必ず守ってください。

- 現在のworkspace外を変更しないこと
- `sudo`を使用しないこと
- GitHubへpushしないこと
- 認証情報を読み取らないこと
- 要求されていない機能を追加しないこと
- 設計書を無断で変更しないこと
- テスト失敗を隠さないこと
- 参考リポジトリをそのまま複製しないこと
- 今回の小規模サンプルに必要な範囲へ縮小すること

## 10．完了条件

次をすべて満たした場合に完了としてください。

- ソースコードが作成されている
- テストコードが作成されている
- `README.md`が作成されている
- `dotnet build`が成功している
- `dotnet test`が成功している
- 要求された文字列の出力を確認している
- `reports/build-result.md`が作成されている
- `reports/test-result.md`が作成されている
- `reports/final-report.md`が作成されている
- 要求、設計、実装、テストの対応関係が説明されている
- 未解決事項が明記されている
- 設計変更が必要な場合は理由が記録されている

完了後は、作成・更新したファイル、ビルド結果、テスト結果、未解決事項を簡潔に報告してください。
