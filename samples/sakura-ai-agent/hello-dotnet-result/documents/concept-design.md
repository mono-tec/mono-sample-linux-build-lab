# 概念設計書

## 1. 開発目的

Linux Build Lab 環境でビルドおよび実行が可能な、最小構成の .NET 10 コンソールアプリケーションを作成する。  
本アプリケーションは、開発環境の動作確認および .NET 10 / Linux 対応のサンプルとして利用されることを目的とする。

## 2. 対象範囲

- コンソールアプリケーション本体（固定文字列の標準出力）
- MSTest を用いた単体テスト
- ビルドおよびテストの手順

## 3. 対象外

- 外部システム連携
- 設定ファイル、ログファイルの出力
- パッケージング（deb / rpm / インストーラ）
- 定期実行制御、デーモン化
- CI/CD パイプライン
- 要求に明示されていない機能

## 4. システム概要

起動時に固定文字列 `Hello from Linux Build Lab` を標準出力へ表示し、正常終了する。  
入力・外部依存・状態管理は一切行わない。

```
[ユーザー] ── dotnet run ──> [コンソールアプリ] ── stdout:"Hello from Linux Build Lab"
```

## 5. 想定利用者

- Linux Build Lab の環境利用者
- .NET on Linux のサンプルを必要とする開発者

## 6. 実行環境

- OS: Linux（x64 / ARM64）
- SDK: .NET 10 SDK
- ランタイム: .NET 10

## 7. 採用技術

| 項目 | 採用技術 |
|------|----------|
| 言語 | C# |
| フレームワーク | .NET 10 |
| アプリケーション種別 | Console Application |
| テストフレームワーク | MSTest |
| ビルドシステム | .NET CLI（`dotnet` コマンド） |

## 9. 主要な設計方針

- **最小構成**: 要求された機能のみを実装し、不要な抽象化や層を設けない
- **外部パッケージ不使用**: 業務用途の NuGet パッケージは使用しない（※仮定参照）
- **標準出力検証**: テストコードは標準出力の内容をキャプチャして検証する

## 10. 制約

- workspace 外を変更しない
- `sudo` を使用しない
- 認証情報を読み取らない
- ソースコード・テストコードは本工程では作成しない
- GitHub へ push しない

## 11. 前提条件

- .NET 10 SDK がインストール済みであること（実装担当が確認・対応）
- Linux 上で `dotnet` CLI が使用可能であること

## 12. 未確定事項

- プロジェクト名およびソリューション名の正式な命名規則（参考リポジトリに準拠して合理的に決定）

## 13. 合理的な仮定

| No | 仮定内容 | 根拠 |
|----|----------|------|
| 1 | プロジェクト名は `HelloLinuxBuildLab` とする | 要求に名称指定がないため、出力内容から簡潔に命名 |
| 2 | 名前空間はプロジェクト名に一致させる | .NET の標準的な慣習に従う |
| 3 | MSTest 実行に必要な標準 NuGet パッケージ（`Microsoft.NET.Test.Sdk`, `MSTest.TestAdapter`, `MSTest.TestFramework`）は使用を許可する | 要求に「MSTestを使用する」とあり、かつ「外部NuGetパッケージは使用しない」が矛盾しないよう interprete するため。業務用途の追加パッケージは使用しない |
| 4 | テスト対象となるエントリポイントは `Program` クラスの `Main` メソッド（または top-level statements における出力ロジック）とする | 最小構成のコンソールアプリの標準的な実装形態 |
